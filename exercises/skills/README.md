# 나만의 SKILL.md 실습 (13분)

목표는 자신의 앱 아이디어를 명세로 바꾸는 절차를 직접 작성하고 개선하는 것입니다. 이 예제는 수업용이며 자동 설치되지 않습니다.

1. **2분:** [예제 SKILL.md](idea-to-spec/SKILL.md)의 이름·description·절차를 읽고 자기 작업에 맞게 고칩니다.
2. **3분:** 결과 형식을 정하고 한 줄을 직접 수정합니다. 예: 성공 조건을 행동 → 예상 결과 표로 출력.
3. **2분:** 선택한 프로젝트 경로로 파일을 복사합니다.
   - Codex: `.agents/skills/idea-to-spec/SKILL.md` → `$idea-to-spec`
   - Claude Code: `.claude/skills/idea-to-spec/SKILL.md` → `/idea-to-spec`
4. **3분:** 아래 두 입력으로 호출하고 실제 결과를 확인합니다.
5. **3분:** 지침 한 줄을 고치고 같은 입력을 다시 시험합니다.

## 입력과 예상 결과

| 입력 | 예상 결과 |
| --- | --- |
| 학회 발표자용 타이머. 분 입력, 시작·일시정지·초기화, 0일 때 종료 표시 | 세 동작 이내의 명세, 각 동작의 성공 조건과 예외 |
| 연구를 도와주는 앱을 만들고 싶어요 | 사용자와 작업을 확인하는 질문. 임의로 기능을 확정하지 않음 |

## 내 기록

- 내가 바꾼 지침:
- 입력 A 실제 결과 / 예상과의 차이:
- 입력 B 실제 결과 / 예상과의 차이:
- 수정한 한 줄:
- 같은 입력의 재검사 결과:

완료 기준: 파일 1개, 호출 결과 2건, 지침 수정 1건, 재검사 기록. 불러오지 못한 경우 본문을 일반 프롬프트에 붙여 절차를 시험하되, 설치·호출 성공과 구별해 기록합니다.

기능 구현은 별도 요청으로 진행합니다. 생성된 명세의 가정은 사용자가 확인합니다. 기존 함수 수정에는 새 앱 기획용 지침을 그대로 강제하지 말고 범위에 맞게 조정합니다.
