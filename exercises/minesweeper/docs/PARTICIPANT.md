# 참가자 실습 가이드

## 시작 전

GitHub와 Desktop에 로그인한 뒤 수업 저장소를 **내 계정에 Fork → 내 Fork를 Desktop으로 Clone**합니다. AI 앱에서 Clone 안의 `exercises/minesweeper`를 열고 같은 위치의 `index.html`을 브라우저에서 엽니다. 클릭·깃발·다시 시작과 아직 지뢰가 없는 미완성 상태를 먼저 관찰하세요.

Desktop은 Clone 저장소 전체를 관리합니다. 수업에서는 내 Fork의 main에서 작업하며, 기능 하나를 확인할 때마다 **Changes → 변경 비교 → Commit → Push**를 반복합니다. 최신 내 변경을 취소할 때는 History의 **Revert Changes in Commit**을 사용합니다. [저장·복구 안내](../../../docs/GITHUB.md)를 참고하세요.

ZIP은 실행용 대안이며 그 폴더에는 Git 이력이 없습니다. AI 앱과 브라우저가 실제로 같은 Clone 위치를 사용하는지 확인합니다.

## 미션 1 지뢰 배치

대상: `src/engine.js`의 `placeMines(game, safeRow, safeCol, rng)`

- 정확히 `game.mineCount`개를 배치합니다.
- 좌표는 겹치지 않고 첫 클릭한 좌표는 제외합니다.
- `cell.isMine`을 바꾸며, 열린 상태·깃발을 지우지 않습니다.
- `rng`는 0 이상 1 미만을 반환합니다. 항상 같은 값을 반환해도 알고리즘이 종료되어야 합니다.

**요청 예시**

> placeMines만 구현해 주세요. 첫 클릭 칸을 제외한 후보를 만든 뒤 rng로 섞어 앞에서 필요한 개수를 선택하는 방식으로 해 주세요. 다른 미션을 미리 구현하지 마세요. 첫 클릭 안전과 개수·중복을 어떻게 확인할지 알려 주세요.

**확인**: 서로 다른 시작 칸으로 여러 번 새 게임을 시작합니다. 첫 클릭 때문에 패배하지 않아야 합니다. 정확한 지뢰 개수는 개발자 도구 또는 선택 테스트로 확인하세요. 겉으로 첫 클릭이 안전한 것만으로 개수 검증을 끝내지 않습니다.

커밋 예: `첫 클릭을 보호하는 지뢰 배치 구현`

## 미션 2 주변 숫자

대상: `countAdjacentMines(game, row, col)`

- 8방향의 보드 안 좌표만 확인합니다. 자기 자신은 제외합니다.
- `isMine`만 세어 숫자로 반환합니다.
- 모서리, 가장자리, 중앙을 각각 테스트합니다.
- 행 마지막 칸과 다음 행 첫 칸이 이웃이라고 판단하지 않도록 합니다.

**요청 예시**

> countAdjacentMines를 구현해 주세요. getCell로 범위를 확인하고 자기 자신을 제외한 8방향만 세세요. 모서리와 행 경계를 포함한 테스트로 확인해 주세요. 다른 TODO는 유지해 주세요.

수동 예상값 연습:

```text
* . *       중앙(1,1)의 주변 지뢰: 3
. . .       위 가운데(0,1): 2
. * .       왼쪽 아래(2,0): 1
```

좌표는 코드에서 0부터 시작하고 화면의 접근성 이름은 1행 1열부터 표시합니다.

커밋 예: `가장자리를 포함한 주변 지뢰 수 계산`

## 미션 3 빈 영역 열기

대상: `expandEmptyArea(game, startCell)`

- 시작 칸은 이미 열려 있습니다. 주변의 연결된 0칸과 그 경계 숫자 칸을 엽니다.
- 지뢰와 깃발은 열지 않습니다. 숫자 칸에서는 더 퍼지지 않습니다.
- 같은 칸을 계속 재방문하지 않도록 합니다. 반복문과 큐를 권장합니다.

> expandEmptyArea만 구현해 주세요. 시작 칸이 이미 revealed인 점에 유의하세요. 연결된 0과 경계 숫자는 열고 지뢰·깃발은 건너뛰세요. 중복 방문을 막는 방법을 설명하고 미션 3 검사로 확인해 주세요.

커밋 예: `빈 영역과 경계 숫자 자동 열기`

## 미션 4 승리 판정

대상: `hasWon(game)`

- 지뢰가 아닌 모든 칸이 열렸을 때만 `true`입니다.
- 깃발을 10개 놓아도 안전한 칸이 닫혀 있으면 승리하지 않습니다.
- 승리·패배 후에는 보드 입력이 상태를 바꾸지 않아야 합니다.

> hasWon만 구현해 주세요. 안전한 칸의 revealed를 기준으로 판단하고 깃발 수는 조건에 넣지 마세요. revealCell과의 연결 및 종료 후 입력 차단을 확인해 주세요.

커밋 예: `안전 칸 기준 승리 판정 구현`

## 수동 확인표

| 행동 | 예상 결과 |
| --- | --- |
| 새로고침 또는 다시 시작 | 열린 칸 0, 깃발 0, 준비 상태 |
| 닫힌 칸 우클릭 또는 F | 깃발 켜기/끄기 |
| 모바일에서 깃발 모드 후 탭 | 해당 칸의 깃발 전환 |
| 깃발 칸을 열기 | 열리지 않음 |
| 열린 칸에 깃발 | 추가되지 않음 |
| 11번째 깃발 시도 | 최대 10개 제한 안내 |
| 첫 클릭 (미션 1 이후) | 지뢰가 아님 |
| 숫자 칸 (미션 2 이후) | 실제 인접 지뢰 수와 일치 |
| 0칸 (미션 3 이후) | 연결 영역과 경계 숫자만 열림 |
| 지뢰 열기 | 패배, 지뢰 표시, 이후 입력 무시 |
| 모든 안전 칸 열기 (미션 4 이후) | 승리, 이후 입력 무시 |

미션을 완료하기 전의 예상 실패와 새로 생긴 버그를 구분하세요. 자동 검사까지 모두 통과한 뒤에도 실제 화면에서 테스트합니다.

## Skills 사용

이 실습 폴더에는 내용이 같은 `minesweeper-workshop` Skill이 두 경로에 준비돼 있습니다.

- ChatGPT · Codex 앱: `.agents/skills/minesweeper-workshop/SKILL.md` — “minesweeper-workshop Skill을 사용해 미션 1만 구현해 주세요.”
- Claude · Code 앱: `.claude/skills/minesweeper-workshop/SKILL.md` — `/minesweeper-workshop 미션 1만 구현해 주세요.`
- Antigravity 앱: `.agents/skills/minesweeper-workshop/SKILL.md` — `/minesweeper-workshop 미션 1만 구현해 주세요.`

경로는 앱에서 연 `minesweeper` 폴더 기준입니다. 도구·버전에 따라 목록과 호출 방식은 다를 수 있습니다. 사용할 수 없으면 해당 `SKILL.md`의 본문을 프롬프트에 붙여 넣을 수 있습니다. 이는 일반 프롬프트 사용이며 Skill로 불러왔다고 기록하지 않습니다. 나만의 `game-check` 작성은 [15분 실습 안내](../../skills/README.md)를 참고합니다.

## 로컬 작업이 어려운 경우 · 선택 대안

1. GitHub 웹에서 본인 Fork를 만듭니다.
2. `src/engine.js`를 AI 채팅에 제공하고 한 미션의 수정만 요청합니다.
3. 본인 Fork의 파일 편집 화면에 반영하고 작은 커밋을 만듭니다.
4. 본인 Fork의 `Code > Download ZIP`으로 내려받고 압축을 풉니다.
5. 내려받은 `index.html`을 브라우저에서 엽니다. 다음 변경 후에는 ZIP도 다시 받아야 합니다.

이 방법에서는 GitHub 웹의 커밋이 바로 원격에 기록됩니다. Desktop의 로컬 Push와 혼동하지 마세요. 자동 실행·배포 또는 GitHub 유료 기능은 필요 없습니다.

## 자신만의 개선 한 가지

핵심 규칙이 작동하면 다음 중 하나를 고르세요: 색·타이포 변경, 타이머, 난이도, 첫 클릭 주변까지 보호, 화면 안내 개선. 난이도를 추가한다면 화면의 고정 9 × 9, 10개 표기와 CSS·깃발 제한 안내도 함께 수정해야 합니다.

새 기능의 성공 조건을 적고, 기존 열기·깃발·리셋·종료 상태를 다시 검사하세요.
