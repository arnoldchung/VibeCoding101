# 바이브 코딩 기초

## 이번 수업의 목표

자연어로 의도를 설명하고, AI가 작성한 코드를 실행·검토하며 작은 단위로 수정합니다. 코드를 모두 외우는 것보다 원하는 동작을 명확히 쓰고, 결과를 직접 확인할 수 있는 것이 목표입니다.

연구자는 문제와 데이터의 의미, 성공 조건을 결정합니다. AI는 구현 초안, 설명, 수정안을 만드는 일을 돕습니다. AI의 설명은 실제 실행과 검증을 대신하지 않습니다.

## 기획 만들기 테스트 개선

1. **기획:** 누가 어떤 작업에서 어려움을 겪는지 정합니다. 첫 버전의 기능을 세 개 이내로 줄입니다.
2. **만들기:** 입력·처리·출력과 성공 조건을 AI에게 설명합니다. 가장 작은 동작부터 요청합니다.
3. **테스트:** 정상 입력뿐 아니라 빈 입력, 반복 클릭, 경계 상황을 확인합니다.
4. **개선:** 한 가지를 바꾸고 기존 기능도 다시 확인한 뒤 변경을 커밋합니다.

## 웹 앱을 이해하는 최소 개념

| 개념 | 의미 |
| --- | --- |
| HTML | 입력창, 버튼, 목록 같은 화면 구조 |
| CSS | 글자, 색, 간격 등 표현 방식 |
| JavaScript | 클릭 반응과 데이터 처리 규칙 |
| 상태 | 앱이 현재 기억하는 입력, 선택, 진행 상황 |
| 함수 | 이름을 붙인 작업 묶음 |
| 프로토타입 | 작업 흐름과 동작을 시험하는 초기 구현 |

처음에는 화면 하나, 사용자 한 명, 외부 서비스 없이 실행하는 범위를 권장합니다. 실제 연구 자료 대신 가상 입력으로 확인합니다.

## 첫 요청문 틀

```text
[사용자]의 [작업]을 돕는 작은 웹 앱을 만들어 주세요.
입력: [사용자가 제공하는 값]
동작: [핵심 기능 1~3개]
출력: [사용자가 확인할 결과]
성공 조건: [어떤 행동에 어떤 결과가 나와야 하는지]
예외: [빈 입력, 중복, 범위 밖 입력의 처리]
제약: 한 화면, 외부 API와 추가 패키지 없이 구현해 주세요.
먼저 이해한 동작을 짧게 확인하고 가장 작은 버전부터 만들어 주세요.
변경한 내용과 직접 확인할 테스트를 설명해 주세요.
```

## 오류를 설명하는 방법

“안 돼요” 대신 **행동, 기대 결과, 실제 결과**를 함께 전달합니다.

```text
상태: [오류 발생 전 상황]
행동: [재현 순서]
기대: [나와야 할 결과]
실제: [관찰한 결과 또는 오류 문장]
이 문제를 수정하고, 같은 절차와 기존 기능을 다시 확인해 주세요.
```

AI가 실행했다고 보고한 검사와 본인이 직접 관찰한 검사를 구별해 기록합니다. 코드 검토만 수행했다면 실행 확인으로 표시하지 않습니다.

## 첫 버전의 완료 기준

- 핵심 동작을 대표 입력으로 시연할 수 있습니다.
- 예상 결과와 실제 결과를 비교한 기록이 있습니다.
- 작동하는 버전의 커밋과 실행 방법을 남겼습니다.
- 아직 확인하지 못한 동작과 실사용 전 추가 검토를 설명할 수 있습니다.
