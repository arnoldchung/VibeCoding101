# 2시간 수업 안내

대상은 코딩 경험이 없는 성인 연구자입니다. 수업의 중심은 바이브 코딩의 작업 방식과 GitHub를 이용한 변경 관리입니다. 지뢰찾기는 이 과정을 함께 연습하는 수업 예제로 사용합니다.

## 첫 60분 함께 배우고 실습하기

| 시간 | 활동 |
| --- | --- |
| 0–10분 | 바이브 코딩 개념과 연구자의 설계·검증 역할 |
| 10–20분 | GitHub와 버전 관리, 저장·커밋·Push의 차이 |
| 20–30분 | 본인 Fork를 Clone하고 README 변경·Diff·커밋 확인 |
| 30–55분 | 지뢰찾기 스타터에서 한 규칙씩 요청·구현·검증 |
| 55–60분 | 작동 버전 기록과 다음 시간의 목표 정리 |

[지뢰찾기 실습](../exercises/minesweeper/README.md)은 먼저 화면을 실행한 뒤 지뢰 배치와 주변 숫자를 구현합니다. 모든 미션을 첫 시간에 완성하는 것이 필수는 아닙니다.

## 다음 60분 내 아이디어 만들기

| 경과 시간 | 활동 |
| --- | --- |
| 0–10분 | 사용자·문제·핵심 기능과 성공 조건 정리 |
| 10–30분 | 가장 작은 첫 버전 생성과 실행 |
| 30–45분 | 짝 테스트, 오류 재현과 수정 |
| 45–55분 | 개선 한 가지, 재검사, 커밋·Push |
| 55–60분 | 결과 시연과 검증 범위·남은 한계 공유 |

지뢰찾기를 계속 확장하거나 자신의 업무·관심사에 맞는 다른 작은 앱을 만들어도 됩니다. 새 프로젝트는 `projects/내-프로젝트/`처럼 실습 폴더와 구분해 둡니다.

## 기획 기록

- 누구의 어떤 작업을 돕나요?
- 사용자가 입력하는 것과 얻는 결과는 무엇인가요?
- 첫 버전에 꼭 필요한 동작 세 개는 무엇인가요?
- 어떤 행동에서 어떤 결과가 나오면 성공인가요?
- 지금은 제외할 기능은 무엇인가요?

## 최종 시연

> 저는 ___를 위한 ___를 만들었습니다. ___를 입력하면 ___가 됩니다. ___ 사례를 확인했으며, ___는 아직 확인하지 못했습니다. 변경 기록은 ___ 커밋에서 볼 수 있습니다.

브랜치·PR 전체 연습은 시간이 남거나 수업 후에 진행합니다. 계정·설치 문제로 제작 시간을 소진하지 않도록 사전 준비 또는 짝 활동을 활용합니다.
