작업 모드

Plan · Edit · Auto: 작업 방식과 권한

Plan-mode

문제를 이해하고 변경 계획을 세웁니다.

파일·성공 조건·검사 방법을 먼저 합의합니다.

Edit-mode

합의한 범위의 파일을 수정합니다.

변경 후 Diff와 동작을 확인합니다.

Auto-mode

도구의 승인 정책 안에서 실행을 이어 갑니다.

자동 진행이 정확성을 보장하지는 않습니다.

이 세 이름은 모든 도구의 공통 메뉴가 아닙니다. 선택한 도구의 실제 모드와 권한을 확인하세요.

작업 모드

도구의 모드 이름을 구별하기

Claude Code

  • plan: 소스 변경 전에 조사·계획
  • acceptEdits: 작업 범위의 편집과 일부 파일 명령 자동 승인
  • auto: 도구 요청을 분류기로 검토해 자동 승인 여부 결정

Codex

  • /plan: 계획 모드로 전환
  • 구현은 사용 중인 환경의 실행·승인 설정을 따름
  • Claude의 auto·acceptEdits와 같은 메뉴라고 가정하지 않음

자동 승인과 모든 권한 허용은 다릅니다. 이 수업은 권한 검사를 끄는 설정을 요구하지 않습니다.

GitHub

버전 관리는 변경의 연구 기록입니다

Git: 내 컴퓨터의 변경 이력

  • 저장소: 파일과 이력을 묶은 프로젝트
  • 커밋: 선택한 변경을 기록한 시점
  • Diff: 이전과 달라진 내용 비교
  • 커밋 ID: 특정 기록을 식별하는 값

GitHub: 이력을 원격에서 공유

  • 원격 저장소에 커밋 업로드
  • 다른 컴퓨터와 변경 동기화
  • 브랜치와 PR로 검토·협업
  • 코드를 올려도 앱이 자동 배포되지는 않음

AI가 수정하기 전의 작동 버전과 수정 이유를 남깁니다.

저장만 하면 커밋이 없고, 로컬 커밋만 하면 GitHub에는 아직 없습니다.

GitHub

준비 상태: 같은 저장소와 작업 폴더

  • GitHub 계정과 GitHub Desktop 로그인을 확인합니다
  • 강사 저장소 arnoldchung/VibeCoding101을 Fork합니다
  • 본인 계정의 Fork를 Clone합니다
  • Clone 폴더를 열고 실습은 exercises/minesweeper에서 진행합니다

Fork는 GitHub의 내 복사본, Clone은 내 컴퓨터의 작업 폴더입니다.

GitHub

실습: README 한 줄을 두 번 기록

  • README에 “상태: 기획 완료”를 적고 저장합니다
  • Changes에서 Diff 확인, 커밋 후 Push합니다
  • “상태: 첫 실습 진행”으로 바꾸고 다시 기록합니다
  • GitHub에서 두 커밋과 변경 내용을 확인합니다

메시지 예: “수업 목표 기록” / “실습 진행 상태 갱신”

GitHub

되돌리기도 새로운 기록으로 남기기

  • 커밋하지 않은 변경이 없는지 확인합니다
  • History에서 방금 만든 두 번째 커밋을 고릅니다
  • Revert Changes in Commit 후 결과를 확인합니다
  • Push하고 README와 원격 이력을 확인합니다

원래 커밋은 남고, 그 변경을 취소하는 새 커밋이 생깁니다.

함께하는 실습

수업 예제: 작은 규칙으로 구성된 지뢰찾기

관찰할 동작

  • 칸을 열거나 깃발을 표시한다
  • 숫자로 주변 지뢰 개수를 확인한다
  • 안전한 칸을 모두 열면 승리한다

스타터의 네 가지 미션

  • ① 첫 클릭을 보호하는 지뢰 배치
  • ② 주변 8칸의 지뢰 수 계산
  • ③ 빈 영역 연결과 ④ 승리 판정

함께하는 시간에는 미션 1–2를 우선합니다. 모든 미션 완성을 첫 시간의 필수 조건으로 삼지 않습니다.

함께하는 실습

데이터 구조가 동작의 기준이 됩니다

칸 하나의 상태

  • row / col: 행과 열 좌표
  • isMine: 지뢰 여부
  • isRevealed: 열린 상태
  • isFlagged: 깃발 표시 여부

게임의 규칙과 상태

  • 지뢰 개수와 보드 크기
  • 첫 클릭 좌표 보호
  • 깃발 칸을 여는 동작 제한
  • 새 게임에서는 상태 초기화

필드 이름과 함수 인수는 스타터의 src/engine.js에서 확인합니다.

함께하는 실습

첫 구현과 실행

  • 스타터 화면에서 클릭·깃발·리셋을 먼저 확인합니다
  • placeMines 한 함수의 계획과 구현을 요청합니다
  • 첫 클릭 안전·지뢰 개수·중복 여부를 검사합니다
  • Diff를 읽고 작동 상태를 커밋한 뒤 Push합니다

실습 화면: exercises/minesweeper/index.html · 테스트는 실습 README 안내를 따릅니다.

함께하는 실습

코드 설명은 동작을 따라 요청합니다

한 동작을 추적하기

  • 칸을 누르면 어떤 함수가 실행되나?
  • 첫 클릭 보호는 어디에 구현되나?
