01 · 바이브 코딩 이해

Plan · Edit · Auto: 작업 방식과 권한

Plan-mode

문제를 이해하고 변경 계획을 세웁니다.

수정할 파일과 성공 조건, 확인 방법을 먼저 정합니다.

Edit-mode

정해 둔 범위에서 파일을 수정합니다.

변경 후 Diff와 동작을 확인합니다.

Auto-mode

설정된 권한 안에서 작업을 자동으로 이어 갑니다.

자동으로 진행해도 결과는 확인해야 합니다.

이 세 이름은 모든 도구의 공통 메뉴가 아닙니다. 선택한 도구의 실제 모드와 권한을 확인하세요.

프롬프트에 무엇을 담을까?

  • 요구사항: 입력·동작·결과

무엇을 확인할까?

  • 성공 조건: 어떤 결과가 나와야 하는가
  • 예외: 빈 입력·범위 밖 값
  • 검사: 무엇을 직접 실행할지
  • 결과 보고: 수정 내용·테스트 결과·남은 작업

02 · 프롬프트 작성

막연한 요청을 구체적으로 바꾸기

“발표 타이머를 만들어 줘”
사용자와 필요한 기능, 종료 조건이 빠져 있습니다.
“발표 시간을 관리하는 한 화면 타이머”
분 단위 시간을 입력하고 시작·일시정지·초기화를 제공합니다.
성공 조건과 예외
0이 되면 종료 표시. 빈 값이나 0 이하의 시간은 시작하지 않고 안내합니다.

02 · 프롬프트 작성

함께 작성할 첫 프롬프트

발표 시간을 관리하는 한 화면 타이머를 만들고 싶습니다.
입력: 0보다 큰 시간(분 단위)
동작: 시작, 일시정지, 초기화
결과: 남은 시간과 종료 상태 표시
제약: 외부 API 없이 브라우저에서 실행
성공 조건: 일시정지 중에는 시간이 줄지 않음
예외: 빈 입력·0 이하 값은 시작하지 않고 안내
먼저 구현 계획만 제시하고, 아직 파일은 수정하지 마세요.

계획을 확인한 뒤 구현을 요청합니다. 처음에는 꼭 필요한 기능만 요청합니다.

02 · 프롬프트 작성

짧은 실습 · 내 프롬프트 다듬기

  1. 반복 작업 하나를 한 문장으로 씁니다.
  2. 사용자·입력·동작·출력을 덧붙입니다.
  3. 성공 조건 한 개와 예외 한 개를 씁니다.
  4. 짝과 요청문을 바꿔 읽고 성공 조건이 분명한지 확인합니다.

2분 작성 + 1분 비교 · 이 요청문을 뒤의 Skill 제작 실습에서 다시 사용합니다.

04 · 나만의 Skill 제작

6 · 한 줄 수정하고 같은 입력으로 재검사

  1. A·B의 실제 결과를 성공 조건과 비교합니다.
  2. 빠진 항목이나 불필요하게 넓어진 범위를 찾습니다.
  3. Skill 지침 한 줄을 수정합니다.
  4. 같은 입력으로 다시 호출하고 전후 차이를 기록합니다.

완료 기준: SKILL.md 파일 + 호출 결과 2건 + 지침 수정 1건 + 재검사 기록

마무리 실습 · GitHub와 지뢰찾기

앞에서 배운 요청과 절차를
작은 코드 변경에 적용합니다.

  1. 본인 Fork의 작업 폴더를 확인합니다.
  2. 구현할 한 규칙을 명세로 씁니다.
  3. 계획 → 수정 → 검증을 진행합니다.
  4. Diff를 읽고 커밋·Push로 기록합니다.

마무리 실습 · GitHub

저장·커밋·Push는 서로 다릅니다

저장

편집한 파일을
작업 폴더에 반영

커밋

Diff를 확인하고
내 이력에 기록

Push

내 커밋을
GitHub에 업로드

Pull

원격의 변경을
내 폴더에 반영

저장만 하면 커밋이 없고, 로컬 커밋만 하면 GitHub에는 아직 없습니다.

마무리 실습 · GitHub

내 저장소에 변경 내용 기록하기

  1. 강사 저장소를 Fork → 본인 Fork를 Clone합니다.
  2. README에 오늘 만든 Skill의 목적 한 줄을 적습니다.
  3. Diff 확인 → 커밋 메시지 작성 → Push합니다.
  4. GitHub에서 파일과 커밋이 반영됐는지 확인합니다.

사전 준비를 마친 참가자는 2분 내 진행합니다. 설치가 막히면 짝 활동으로 변경 흐름을 확인합니다.

마무리 실습 · 지뢰찾기

지뢰찾기 · 한 가지 규칙의 요구사항 정하기

대상: placeMines(game, safeRow, safeCol, rng)

  • 9×9 보드에 지뢰 10개, 중복 좌표 없음
  • 첫 클릭한 좌표에는 지뢰 없음
  • rng가 같은 값을 반복해도 배치가 종료됨
  • 다른 TODO와 기존 클릭·깃발·리셋은 유지

내 idea-to-spec Skill로 이 조건을 정리해도 됩니다. 다만 “한 화면·세 동작”은 새 앱을 위한 조건이므로 기존 함수를 수정할 때는 지침을 조정하세요.

마무리 실습 · 지뢰찾기

계획 · 구현 · 검증 · 기록

  1. “placeMines만 구현할 계획을 설명해 주세요. 아직 수정하지 마세요.”
  2. “합의한 계획으로 이 함수만 수정해 주세요.”
  3. 개수·중복·첫 클릭·종료 여부를 확인합니다.
  4. Diff → Commit → Push로 변경 이유와 검사 결과를 남깁니다.

지뢰찾기 스타터 열기 · 실습 코드와 테스트 안내

첫 시간에는 한 가지 규칙을 구현하고 확인합니다. 나머지 미션은 추가로 도전해 보세요.
